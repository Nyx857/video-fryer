# 全损视频生成器(video-fryer)设计文档

日期:2026-08-02
状态:已由用户确认

## 1. 目标

做一个免费、纯前端、手机可用的在线"全损视频生成器":上传一段视频,在浏览器本地把它处理成「全损画质 + 收音机烂音」的 MP4,下载后发给朋友整蛊。效果像"被微信/QQ 传了一万次"。

## 2. 非目标(本次不做)

- 不做深油炸滤镜、倒放、慢放、卡顿循环等花哨玩法
- 不做多档强度调节(先固定一档"全损")
- 不做服务端处理(无服务器、无后端),视频不上传
- 不处理图片(图片已有 image-compressor)

## 3. 功能需求

### 3.1 上传
- 点击/拖拽上传,手机端用大按钮(避免拖拽在手机上不可用的陷阱)
- 限制:时长 ≤ 3 分钟、大小 ≤ 200MB(保护手机内存,超出给中文提示)

### 3.2 引擎加载
- 首次加载 ffmpeg.wasm 时显示进度条与说明(约 25MB,视网速 10~30 秒)
- 浏览器缓存后二次打开秒加载

### 3.3 处理
- 显示实时进度百分比(基于 ffmpeg progress 回调)
- 处理期间禁用重复操作,可取消

### 3.4 结果
- 原片 vs 烂片并排预览对比
- 下载按钮,文件名自动命名 `原名_全损.mp4`

### 3.5 隐私卖点
- 页面显著位置注明:"视频在本地处理,不上传服务器"

## 4. 全损效果参数(基线,实现时调优)

### 4.1 视频
- 缩放:约 240p(`scale=320:-2`)
- 码率:低码率 H.264(`-b:v 250k`),产生真实压缩伪影/马赛克块
- 噪点:轻微 `noise` 滤镜增强"烂"感(可选,以效果为准)
- `-pix_fmt yuv420p` 保证播放器兼容
- 输出封装:MP4(H.264)

### 4.2 音频
- `tremolo`(音量忽大忽小)+ `alimiter`(削波爆音),模拟收音机信号差
- 降采样:22050Hz 单声道,低码率 AAC(约 48k),声音变糙
- 输出封装:MP4(AAC)

## 5. 页面布局

1. 顶部:标题 + 隐私卖点("视频在本地处理,不上传")
2. 上传区:点击/拖拽上传
3. 进度区:引擎加载进度 / 处理进度(百分比 + 进度条)
4. 结果区:原片 vs 烂片并排对比预览 + 下载按钮

## 6. 技术设计

### 6.1 架构
纯静态单页应用,无构建、无后端,仅 CDN 引入 ffmpeg.wasm。

文件结构:
```
video-fryer/
├── index.html      # 页面结构
├── style.css       # 样式(响应式)
├── app.js          # UI 交互:上传、进度、结果渲染、下载
└── fry.js          # 处理核心:加载 ffmpeg、构造滤镜命令、读回结果
```

### 6.2 依赖
- `@ffmpeg/ffmpeg` + `@ffmpeg/core`(0.12.x,CDN 引入)
- 使用**单线程版 core**:GitHub Pages 无法设置 COOP/COEP 响应头,多线程(SharedArrayBuffer)不可用
- 其余全部浏览器原生能力

### 6.3 处理流程
```
File → writeFile 写入 MEMFS → exec(滤镜命令) → readFile 读回 → Blob
→ URL.createObjectURL → 预览对比 → 下载
```

### 6.4 滤镜命令(基线)
```
ffmpeg -i input.mp4
  -vf scale=320:-2,noise=alls=10:allf=t
  -b:v 250k
  -af "tremolo=f=0.7:d=0.7,alimiter=limit=0.2"
  -ar 22050 -ac 1 -b:a 48k
  -pix_fmt yuv420p output.mp4
```

## 7. 错误处理

- 非视频文件:拒绝并提示
- 超长/超大:提示限制(≤3 分钟、≤200MB)
- ffmpeg 引擎加载失败:提示检查网络/刷新重试
- 处理失败(含内存不足):捕获异常,提示换更短视频或换设备
- 处理中重复上传:禁用上传区

## 8. 测试

- 桌面 Chrome 实测:上传 → 加载引擎 → 处理 → 对比 → 下载 全流程
- 手机视图(DevTools 模拟):上传、进度、下载可用
- 边界:非视频文件、超长视频、超大文件、处理中取消
- 兼容性:导出的 MP4 在 iPhone(Safari)与微信中确认可播放、可发送

## 9. 部署

- GitHub Pages 免费托管(静态文件直接可用)
- 单线程版 core 从 CDN 加载,无 COOP/COEP 需求
